## 7. Fix scroll interference (user-reported after initial verification)

- [x] 7.1 User feedback: the drag gesture interfered with the Image Library panel's own horizontal scroll — any swipe on a card, including one meant to scroll the shelf, was arming a drag. Requested fix: arm only once a swipe's position is outside the Image Library panel; until then, the panel's own scroll must work normally.
- [x] 7.2 Reworked `useLibraryImageDragGesture`'s arming condition from a fixed pixel threshold to an `isInsidePanel(clientX, clientY)` check supplied by the caller — arms only once a move's position falls outside the panel.
- [x] 7.3 Added an optional `panelRef` prop to `BottomSheet`, forwarded to its own outer element; `MobileShell` attaches it to the `Photos` sheet and uses it to back `isInsidePanel`.
- [x] 7.4 First iteration (`setPointerCapture` on the arming move, deferred from pointerdown) broke on real touch input: without capture from the very start, a card's own `onPointerMove` stops receiving events entirely once the touch physically leaves that ~140px element, well before any exit-the-panel check could fire. Fixed by capturing movement via `window`-level `pointermove`/`pointerup`/`pointercancel` listeners registered on `pointerdown`, independent of which element the browser is currently hit-testing to; `setPointerCapture` itself is deferred until the arm condition is met.
- [x] 7.5 Second iteration (window-level listeners, no `setPointerCapture` until armed) still broke on real touch input: the browser cancels a pointer's entire event sequence the moment it decides the touch might be a native pan/scroll — independent of pointer capture, decided purely from `touch-action` and direction — so a vertical swipe (needed to reach the canvas) was being silently cancelled after one move sample, since the sheet's content wrapper is a plausible (if non-overflowing) scroll target. Fixed with `touch-action: pan-x` on each card: horizontal panning (the shelf's own scroll) stays native, vertical panning is never eligible to be claimed, so the exit-the-panel swipe's events keep flowing.
- [x] 7.6 Re-verified the full flow on the `epp_test` Android emulator with genuine touch input and 8 loaded images (enough for the shelf to actually overflow): a horizontal swipe on a card scrolls the shelf without arming anything or assigning; a vertical swipe off a card still arms, closes the `Photos` sheet, and assigns on drop over a slot. Confirmed via `adb logcat` debug output that the pointer's `armed` state only flips `true` once its position crosses the panel's top edge.
- [x] 7.7 Re-ran the full Electron/Playwright verification (task group 5's script) and the Android manual pass (task group 6) end to end after the fix — both still pass; full Vitest suite (189/189) and typecheck clean.
