## 6. Properties auto-sheet on selection

- [x] 6.1 In `MobileShell`, read `ui.selection` from the store and open a `BottomSheet` showing `PropertiesPanel` (bare) automatically whenever selection is non-null, closing automatically when it's cleared — independent of the tab-bar's own open/closed state (selecting something while a tab sheet is open should switch to the Properties sheet, not stack on top of it). Implementation note (see design.md's addendum to Decision 5, added during this task): `ui.selection` alone can't drive the open/closed state, because `clearSelection()` falls back to the root node instead of nulling the selection in Simple mode. Fixed via local dismissal-key tracking in `MobileShell`, keeping the shared store untouched (user's explicit choice over changing `clearSelection`, to preserve desktop's zero-behavior-change goal).
- [x] 6.2 Verified via Playwright/xvfb at 480x800: selecting the root image slot opens the Properties sheet automatically with no tab bar destination shown active; the sheet's close button and a backdrop tap both close it; opening a tab sheet (Templates) and then selecting the slot replaces it with Properties rather than stacking; tapping a tab bar destination while Properties is open dismisses it and opens that tab. Selecting a freeform element and a library image, plus the empty-canvas-tap path, are covered by the more thorough desktop pass in section 9 and the real-device pass in section 10. Pressing Escape to deselect was found not to work at all — reproduces identically at full desktop width, in `App.tsx`'s pre-existing keydown handler that this change didn't touch, so it's a pre-existing bug outside this change's scope. Flagged to the user rather than fixed here.
